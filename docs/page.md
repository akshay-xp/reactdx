# Page (`packages/page`)

Code that runs in the page's MAIN world: installing the React DevTools global hook, recording what React registers, and (in the injected agent) reading the component tree.

## Rules

- The hook (`src/hook.ts`) has no runtime dependencies (only types from `@reactdx/messages`): it's bundled into the `document_start` script that runs on every site, which `pnpm check` holds to 2,048 bytes (`docs/check.md`). Measured: 1,703 bytes (M2 #20).
- Never imports React; React only reaches it through the hook (`docs/check.md` fails any bundle containing React).

## Installer (`installHook(target, onRenderer?)`, `src/hook.ts`)

React connects to whichever `__REACT_DEVTOOLS_GLOBAL_HOOK__` exists when it loads. RDT 8 won't install its hook when one is already `window`'s own property (it checks `hasOwnProperty` twice), so ReactDX never claims that property. Three paths, all tested against the store RDT in both browsers (`docs/e2e.md`):

| Situation                                             | What `installHook` does                                                                                                                                                                                                                |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A hook is already `window`'s own property (RDT first) | Attaches to it. RDT defines it with a getter, so the check reads `target[KEY]`, not the descriptor's `value`.                                                                                                                          |
| No hook yet (ReactDX first)                           | Creates ours and defines it on `Object.getPrototypeOf(target)` (`Window.prototype`) as a configurable accessor. React finds it through the prototype chain; RDT's `hasOwnProperty` checks don't, so RDT installs normally on `window`. |
| A tool installs after us                              | `Object.defineProperty(window, KEY, …)` (RDT 8): a temporary wrapper attaches as it lands. Plain assignment `window.KEY = hook`: the accessor's `set` defines it as `window`'s own property (as without us) and attaches.              |

- **Attaching** wraps `inject` (records the renderer under the id the hook returned) and `onCommitFiberRoot` (calls the hook's own first, then ours). Renderers already in `hook.renderers` are recorded on attach.
- **Restore:** the `defineProperty` wrapper is removed on the first renderer inject, in any order, unless something else wrapped it since. The page sees a patched built-in only until React connects.
- **Not handled:** RDT enabled after React has connected (for example turned on with the page open). React only injects once, so RDT gets nothing until a reload; that's RDT's own behavior without ReactDX.

## Record (`HookRecord`)

- `installHook(target, onRenderer?)` calls `onRenderer(id, { version, bundleType, rendererPackageName })` once per renderer, including those already on a hook installed first. The content script uses it to post to the relay (`docs/messages.md`).
- `installHook` returns it, and stores it on `target` under `Symbol.for("reactdx")` (non-enumerable), where the injected agent will find it (M2 #21).
- `renderers`: `Map<id, { version, bundleType, rendererPackageName }>`, copied fields only (no references to React's renderer objects).
- `roots`: `Map<id, Set<FiberRoot>>`. A root is added on commit and removed when it commits with no element (`root.current.memoizedState?.element == null`, i.e. `root.unmount()`).
- `listeners`: `Set<(rendererId, root) => void>`, called after every commit.
- Next's Server Components client (`react-server-dom-turbopack`) only registers with a hook that has `supportsFlight`. RDT's hook has it, ours doesn't (yet), so with RDT installed the record lists it too, with no roots. Worth adding to ours for M7.

## Agent (`startAgent(target, post)`, `src/agent.ts`)

- Injected after a development renderer connects (`docs/messages.md`), so it isn't bound by the 2,048-byte budget. Does nothing without the hook record or if already started (`Symbol.for("reactdx.agent")` on `target`).
- Reads `record.roots`, so roots that committed before it arrived are reported. Root ids are its own (a `WeakMap<FiberRoot, { id, commits }>`, counting from 1).
- Commit counts start when the agent starts: existing roots begin at 0.
- Posts `snapshotMessage(roots)` at start, at most every 100 ms after commits (one timer per burst, so a page committing every frame can't flood the extension), and on a `get-snapshot` message event on `target`.
- Unmounted roots drop out of the next snapshot (the record removes them).

## Tree (`createTree()`, `src/tree.ts`; M3 #24)

The agent tracks the component tree only between `WATCH` and `UNWATCH` message events from the relay (`docs/messages.md`, "Tree batches"), so a page with DevTools closed pays nothing beyond M2.

- **Watch:** posts `reset` plus every root's tree, depth-first, starting a new `seq` at 1. Every watch is a full resync.
- **Ids:** a `WeakMap` sets each id on both the fiber and its `alternate` (React swaps them on every update), counting from 1 per document. Ids survive `UNWATCH`, so a re-watch gives the same component the same id.
- **Kinds (by fiber tag):** 0 function, 1 class, 11 forwardRef, 14/15 memo, 9 consumer, 10 provider, 12 profiler, 13 suspense, 31 activity, 5/26/27 host; `lazy` when `elementType` is a lazy wrapper; `server` for a Server Component (no fiber, below). Every other tag (root, text, fragment, mode, portal, offscreen...) emits nothing; its children attach to the nearest emitted ancestor.
- **Names:** `displayName`, then the wrapped component for forwardRef (`render`) and memo (`type`), then `name`, then `Anonymous`. Providers and consumers: the context's `displayName` or `Context`. Host: the tag. Profiler, Suspense, Activity: fixed. Names and keys are cut to 256 chars (`MAX_TREE_STRING`), the validator's bound.
- **Server Components** (M7 #77): React 19 development builds copy the `ReactComponentInfo` of the Server Components around each fiber onto `fiber._debugInfo`, outermost first, beside `{ time }` and `{ awaited }` entries (`docs/m7-findings.md`); entries with a string `name` are the components. They have no fibers, so each becomes a virtual node of kind `server` (name and key from the info) holding the consecutive kids it rendered; the next info in a kid's chain nests inside it, so nesting follows fiber position plus the chain (`owner` isn't used for placement). A keyed Fragment keeps its info on its own fiber, so a skipped fiber's infos prefix its kids' chains. Ids: one per info object (`WeakMap`), from the same counter as fibers; a new payload's info (`router.refresh`, a navigation) named and keyed like a server node already under the same parent takes its id. One info is one node: a second run of it, at the same level or under another parent, gets none (a duplicate id would desync the panel), and its kids attach to the parent. Server nodes have no fiber: `fiber`, `find` and `known` give nothing for them, and visits skip them. A level whose kids carry no info allocates nothing extra. React 18 doesn't write `_debugInfo`, so it gets none.
- **Last child:** React clears a fiber's `alternate.child` too when its last child unmounts, so `bailedOut` needs a non-null `child`; otherwise the emptied node looked bailed out and its last child stayed in the panel.
- **Suspense waits** (M7 #80, `src/suspense.ts`): `waitOf(fiber)` is `"fallback"` or `"dehydrated"` for a boundary (tag 13) with `memoizedState` set (`dehydrated` non-null: server HTML not yet hydrated), else null. `track` runs on a suspense node's add and on each commit's known-kid pass: a boundary that starts waiting emits `{ op: "suspense", id, state: "waiting", ms }` (since now, `ms` 0; a dehydrated one has waited since navigation start, so `ms` is `now()`), one whose content arrived `{ state: "arrived", ms: now() - since }` (and `onArrive(fiber)`), then waiting again a new waiting op. A resync's add sends a wait it already knew again, counted from its start (a resync during a Next navigation showed no wait until arrival). `createTree({ now })` takes the clock (default `performance.now`); `forget` and `clear` drop the waits.
- **Hidden content:** an Offscreen fiber (tag 22) with `memoizedState !== null` is suspended or hidden, so its subtree isn't emitted. A Suspense showing its fallback lists only the fallback.
- **Per-commit diff:** every commit while watched, not once per flush, because the shortcut only holds against the previous commit: a node whose fiber has an `alternate` with the same `child` bailed out, so nothing below it changed. Otherwise its emitted children are compared with the stored list: `remove` the gone (descendants implied), `add` the new in ascending index with their subtrees, then `reorder` if the order still differs. A known child whose name changed (Fast Refresh, a late `displayName`) gets `rename`.
- **Visits:** `commit(root, rootId, ops, onVisit?)` calls `onVisit(fiber, id)` once for each emitted fiber it adds, or reconciles and that did work; never inside a bailed-out subtree, and `full` calls none. Untouched clones (#76, `untouched`): React clones every sibling of an updated fiber; a kept kid with an alternate, no `PerformedWork` flag (1), its alternate's `memoizedProps`, `memoizedState`, `child` and `type`, and neither fiber in `root.memoizedUpdaters` (read at `commit`'s start; dev builds) is stored (`fibers.set`) but not renamed, tracked, visited or walked into. The updaters condition: a component re-run by its own update with nothing changed bails out with no flag, and the recorder counts it as a render. Caveat: a `displayName` set on a component that doesn't re-render shows at its next render. Saving: the hook's one-cell time under 10,000 cells -30% locally, -35 to -41% on CI (findings on #76); still storing the fiber, since an untouched kid's stored alternate is what React reuses as the next work-in-progress (skipping it measured -46 to -55% but needs a current-fiber resolver). That includes kids under a skipped wrapper that bailed out (`bailedOut`: `child === alternate.child`, e.g. the Fragment of a constant children array): React didn't clone them, so they're last commit's fibers, with no alternate and their mount's flags (`visible` collects them as `stale`; they're neither visited nor walked below, like a bailed-out emitted node). Recording them read 10,000 bailed-out cells as mounts (M6 #67). Cost (M6 #67, `e2e/perf.test.ts`): a parent whose child ids are unchanged skips the remove/add/reorder bookkeeping (`same`; a one-cell commit under 10,000 cells clones them all, so the parent is walked every time), `idOf` writes nothing on a hit, and the recorder keeps ids only for new fibers (`remountOf` looks up no others). M6 render recording rides this walk.
- **Posting:** ops are buffered and posted on the existing 100 ms flush, split into batches of at most 2,000 (`MAX_OPS`), each with the next `seq`. A commit with no structural change posts nothing.
- **Unwatch:** stops diffing, drops the buffer and the stored children, names and fibers, and hides the highlight.
- **`find(id)`** (M3 #28): `{ name, elements }` for an emitted node, or `undefined` (unknown or removed). `elements` are its top-level DOM elements: the first host fibers (5, 26, 27) below it, their `stateNode`; a host node gives itself; text is skipped, and so is hidden Offscreen content. A server node (M7 #78) gives its children's elements in order, nested server nodes included, so hovering a server row highlights what it rendered. The tree keeps the latest fiber per id (set on add and on each commit's visit). A bailed-out subtree shares its child fibers, so the ones kept there stay current.

## Highlight (`createOverlay(doc)`, `src/overlay.ts`; M3 #28)

- The agent handles `highlight` (`{ source: "reactdx-relay", type: "highlight", id }`): `show(find(id)?.elements ?? [], name)`. `clear-highlight` and `unwatch` call `hide()`. The page can post these too; an id the tree doesn't know shows nothing.
- `show(elements, label)`: one `div` appended to `document.documentElement` on first show, with inline `position: fixed; inset: 0; pointer-events: none; z-index: 2147483647` and a closed shadow root (page CSS can't restyle it, page queries don't find the boxes). Inside: a `[data-box]` per element at its `getBoundingClientRect()`, and the label as a text node above the first box. Each show rebuilds the contents. `show([])` hides.
- `hide()`: removes the host. Page elements' styles and layout are never touched (`e2e/highlight.test.ts` compares every computed style).
- Not repositioned on scroll or resize while shown.

## Outlines (`src/outlines.ts`; M7 #82, #83)

Outlines on the page, off until the panel's `outlines { mode }` command: `"suspense"`, `"islands"`, or `null` (off). One mode draws at a time, on one layer; `unwatch` turns both off. Cost rules from `docs/m7-findings.md`, spike 2.

- `createOutlineLayer(doc).draw(outlines, more)`: its own host beside the hover overlay's (a hover doesn't wipe them), the same fixed, click-through, closed-shadow host on `documentElement`. Each `Outline` `{ left, top, width, height, label, style }` is a `[data-outline]` div (`data-style` `waiting` or `arrived`) with a 2px `outline` (not a border, so its rect is the element's) and its label above it; `more` > 0 adds `[data-more]` "N more outlines". `draw([], 0)` removes the host. Colors are the panel theme's light values (the page doesn't know the panel's theme): waiting `#8a5a00`, arrived (`success`) `#188038`, white label text.
- `boxOf(elements)`: one rectangle per component, the union of its top elements' rects (`tree.find(id).elements`), skipping empty ones (`display: none`); undefined when none.
- `createScheduler({ target, frame, measure })` `{ start, stop, changed, active }` (both modes): `measure` on the next animation frame after `changed()` (one frame per burst), never inside the commit hook (the agent's commit listener only calls `changed()`); while started, a capture, passive `scroll` listener (every scroller) and `resize` on the window call `changed()` too. A frame queued before `stop()` measures nothing.
- `createSuspenseOutlines({ layer, target, waits, find, causeFor, now, frame })` `{ on, off, changed, arrived }`: each frame measures at most 100 (`MAX_OUTLINES`) of the tree's waits (`tree.waits()`), then the arrivals, and counts the rest as `more`. Labels: "waiting 1.2s" (`durationText`) plus the cause (`causeOf` with React 18's record): " · Reviews (server)", " · thrown by Comments", " · in Comments" (React 19's child element); a lazy or promise adds nothing. `arrived(id, ms)` (from `onArrive`): "arrived in 840 ms" in the arrived style for 2 s, then gone. While a waiting outline shows, a 100 ms interval redraws the labels from the last frame's boxes without measuring.
- A dehydrated boundary (streamed, not hydrated) has no child fibers: `tree.find` gives its server HTML, the elements between its `<!--$?-->` (or `$`, `$!`) comment (`memoizedState.dehydrated`) and the matching `<!--/$-->`, nested markers counted. The hover highlight gets them too.
- Client islands (M7 #83): `tree.islands()` lists, in tree order, each component whose nearest component ancestor is a server node (`{ id, name, kind, server, wraps }`); `wraps` when a server node renders under it, a client wrapper around server children (a `"use client"` ThemeProvider). React's own providers aren't components, so never islands. The agent drops Next's own (`nextInternal(name, kind)` from messages: `__next_*` boundaries, `OuterLayoutRouter`, whose box is the whole page) and adds the server node's name and `sizeOf(memoizedProps)`, cached per props object. `createIslandOutlines({ layer, target, islands, find, frame, onPick })` `{ on, off, changed }`: lit islands `style: "island"` ("AddToCart · 14.3 KB"), wrappers `"wrapper"`, dashed and not lit ("ThemeProvider · 12 B · wraps server content"), at most 100; the layer's `dim` shades the viewport but the lit islands (an svg path, `fill-rule="evenodd"`, `[data-dim]`), and `[data-summary]` counts every island, drawn or not: "3 client islands · N KB of props" (`sizeText` of the sum). While on, capture listeners on the window hit-test the last frame's boxes (a lit island before a wrapper around it): `pointermove` adds " · from ProductDetails" to the island under the pointer; a press on one (`pointerdown`, `mousedown`, `pointerup`, `mouseup`, `click`) is swallowed, and its `click` posts `picked(id)`, which the panel selects as the picker's. Presses elsewhere reach the page. Island color is the theme's light `client` (`#a04f00`).
- Not done: a layout shift with no commit, scroll or resize (no `ResizeObserver`), which spike 2 left untested.

## Picker (`src/agent.ts`; M3 #29)

- `tree.owner(element)`: walks DOM parents to the first element with a `__reactFiber$…` key, then `fiber.return` to the nearest fiber with a kind that isn't `host`, whose id the tree still has (mounted and emitted). So a pick is always a component, with a row even when DOM elements are hidden. `undefined` outside React.
- `pick-start` adds capture-phase listeners on the window, ahead of React's on the root container:
  - `pointermove`: highlights the owner of the element under the pointer (hides the overlay over anything React doesn't own).
  - `pointerdown`, `mousedown`, `pointerup`, `mouseup`: `preventDefault` and `stopImmediatePropagation`, so the app never sees any of the press (pages act on press too: menus, drags, focus); as React DevTools does. A prevented `pointerdown` still lets the `click` fire.
  - `click`: `preventDefault` and `stopImmediatePropagation` (the app never sees it), ends picking, posts `picked(owner ?? null)`.
  - `keydown` Escape: ends picking, posts `picked(null)`.
- Ending picking removes the listeners and hides the overlay. `pick-stop` and `unwatch` end it without posting. Only `click` is swallowed: `pointerdown` and `mousedown` still reach the page.

## Values (`createInspector()`, `src/inspect.ts`; M4 #33)

Describes page values for the inspector. Carried from the M0 #7 spike (`docs/m0-findings.md`, "Value format for the panel"), with its gaps fixed. Every result is JSON-safe and passes `parseValue` (`docs/messages.md`, "Inspected values").

- `{ serialize(value), expand(id, offset = 0), find(id, key?), release() }`. Objects get ids (a `WeakMap` and an id-to-object `Map`, from 1); the same object keeps its id until `release()`. `expand` of an id it doesn't hold returns `undefined`. `find` returns `{ value }`: the object, or with `key` its child: a property by name as sent (bounded, symbols as `Symbol(desc)`), or a number indexing an array, typed array, map's entries (the value) or set; `undefined` for none, a getter (never run) or a throw.
- Copy (`copyText(value)`): a string as it is; a function its source (`Function.prototype.toString`, not one the app set); anything else as 2-space JSON from a walk that never runs getters: enumerable string keys only (React's dev `key` warning getter isn't), `NaN`/`Infinity` and bigints (`2n`) as strings, functions inside `[Function: name]` (`anonymous` without one: a handler's source would bloat an object's copy), symbols `Symbol(desc)`, maps as `[key, value]` pairs, sets and typed arrays as arrays, summaries as text (`<div />` for elements, ISO dates, `/a/g`, `Error: msg`, `<div>`, `[Promise]`), getters `[Getter]`, cycles `[Circular]`, a throw `[Unreadable]`. Top-level `undefined` is `undefined`.
- Limits: `MAX_DEPTH` 2 (deeper objects are `ref` with a `preview`, one `expand` away), `PAGE` 100 entries per message for every container (object keys too, with `nextOffset`), strings cut to 1,000 chars with their `length`, names (functions, classes, tags, keys, symbol descriptions, error names) to 256, keys, messages and attributes to 1,000.
- Never runs app code on purpose: properties are read through `Object.getOwnPropertyDescriptors`; accessors are `{ type: "getter" }`.
- Descriptors beyond the spike's table: `typed-array` (paged by index: a `Uint8Array(1_000_000)` takes under 5 ms locally; the unit tests allow 50 ms for shared CI runners), `array-buffer` and `data-view` (`byteLength`), `weak-map`, `weak-set`; symbol-keyed props as `"Symbol(desc)"`; an array's non-index props (up to 100) in `props`; sparse holes as `{ type: "hole" }`.
- Proxies can't be detected, so their traps run. Anything that throws while read becomes `{ type: "unreadable", message }` and its siblings still serialize.
- `test/inspect.test.ts`: the spike's cases, every gap, and a mixed value checked against `parseValue`.

## Inspection (`src/agent.ts`; M4 #33)

- `inspect { id }` (checked with `parseTreeCommand`): releases the previous inspection, starts a new `createInspector()`, and posts `inspected(id, data)`: `{ props }` from the fiber's `memoizedProps` (every kind, host nodes included), plus `state` from a class instance (tag 1) when it isn't null. An id the tree doesn't have gets `data: null`. `inspect { id: null }` stops.
- Live: on the existing 100 ms flush, re-sent only when the fiber `tree.fiber(id)` returns has a different `memoizedProps` or `memoizedState` from the last send (React gives a rendered fiber new ones), so commits elsewhere cost a comparison. An unmounted node gets one `data: null` and the inspection ends.
- `expand { objectId, offset }`: posts `expanded(objectId, offset, value)` from the current inspection; ids it doesn't hold (released, forged) post nothing.
- `edit { id, root, path, value }` (M5 #50, `src/edit.ts`): only for the inspected node (`id === selected.id`) and a fiber the tree holds. `fromEditValue` decodes the value (markers to `undefined`, `NaN`, `Infinity`, `-Infinity`, `-0`; tagged objects to plain ones). `applyEdit(renderer, fiber, root, path, op, hooks)` (`op`: an `EditOp`, `{ op: "set", value }`, `{ op: "delete" }` or `{ op: "rename", to }`, from `edit`, `delete-path` and `rename-path`; M5 #53) first checks `plainPath(rootValue, path)` (M5 #51): every container the path writes through, from the root value (`memoizedProps`, the raw hook's value, the instance's state), is an array or an object whose prototype is `Object.prototype` or null, read through descriptors (no getter runs): React's copy would turn a Map, Set or class instance into a plain object. Then `"props"` calls `renderer.overrideProps(fiber, path, value)`, `overridePropsDeletePath(fiber, path)` or `overridePropsRenamePath(fiber, path, newPath)` (hooks: the `overrideHookState` equivalents with the hook's index); a delete or rename needs a key, and a rename an object's key to a name it doesn't have (React's would overwrite it); an array item deleted is spliced out; `"state"` (class components, tag 1, only) replaces the state with a copy through `instance.updater.enqueueReplaceState(instance, next)` (what `createReactClass`'s `replaceState` uses), `next` from `copyWithSet`, `copyWithDelete` or `copyWithRename` (one `copyAlong` walk, copying arrays by slice and objects by spread as React does): React has no override for class state, a render recomputes it from the update queue (setting `instance.state` and `forceUpdate()` is reverted), and `setState` merges, so it can't delete or rename; `{ hook }` finds the raw hook by call indexes (`hookAt`, also used by copy and store) and only a `State`/`Reducer` with an `index` calls `renderer.overrideHookState(fiber, index, path, value)`; anything else is ignored. React copies along the path and schedules a sync render, so `memo`, effect deps and children see a real update. The renderer is `rendererOf(fiber)`: the one whose roots hold the fiber's HostRoot (its `currentDispatcherRef` is what hooks are read with). After an edit the agent calls `refresh` on the next task (`setTimeout`), after React's microtask commit, instead of waiting for the 100 ms flush: the bench page's edit median went from about 117 ms to 27 ms; the flush then finds nothing new.
- `copy-value { target }` / `store-value { target }` (the panel's row menu): the value at a `ValueTarget` of the current inspection: `objectId` (+ `key`) through `find`, `hook` by call indexes through the raw hooks kept from `describe` (a hook without a value: none), `context` by read order from the values sent. None: nothing happens. `copy-value` posts `valueText(copyText(value))` when within `MAX_COPY` (10,000,000 chars). `store-value` sets the next free `$reactdx<n>` (from 1) on the page's window and `console.log`s the name and value, like DevTools' "Store as global variable", then posts `valueStored(name)` so the panel can say where it went.
- `unwatch` ends the inspection; a new watch starts without one (the panel asks again).
- Contexts (M4 #35): `fiber.dependencies.firstContext` (`{ context, memoizedValue, next }`) holds every context read in the last render, whatever read it (`useContext`, `use`, a class's `contextType`, consumers). Listed once each in first-read order as `{ name, value }` (plus `default: true` when `providerOf(fiber, context)` finds no provider above: the nearest fiber with tag 10 whose `type` is the context, React 19, or has it as `_context`, React 18's Provider object; M5 #54), the name the context's `displayName` or `Context` (React's own host transition context, read by `useFormStatus`, is one of these). A re-send also happens when any read value changed (`Object.is`), since a memo'd consumer re-rendered by its provider keeps its props and state objects.
- Source (M4 #36, `src/source.ts`): `sourceOf(fiber)` is the component's own location: the first element it renders, else its own element (where it was rendered). Depth-first from `fiber.child`: a fiber whose `_debugOwner` is the fiber (or its alternate) is the answer; one with no owner (React's own, e.g. Suspense's Offscreen) is searched into; one owned by another component is skipped with its subtree (children passed in are the parent's). React 18: `_debugSource { fileName, lineNumber, columnNumber }` (1-based, from the JSX transform) gives `{ file, line, column }`. React 19 has no `_debugSource`; `_debugStack` is `Error("react-stack-top-frame")` made in `jsxDEV`/`createElement`, so `stackSource(stack)` takes frame 1 (V8 `at fn (url:l:c)` / `at url:l:c`, Firefox `fn@url:l:c`) as `{ url, line, column }`, which the panel maps through source maps. Frame 0 `UnknownOwner` (past React's owner stack limit) means no location.
- Owners (M4 #35): the `_debugOwner` chain, nearest first, at most 50 (`MAX_OWNERS`). A fiber the tree has emitted and still holds gives `{ id, name }` (`tree.known(fiber)`, either of its two fibers); others are skipped. A React 19 Server Component (`ReactComponentInfo`, no `tag`) gives `{ id, name }`, `id` its mounted server node's (M7 #79) or null, and the chain continues through its `owner`.
- `tree.fiber(id)`: the node's fiber as of the last commit.
- Suspense (M7 #80, `src/suspense.ts`): a waiting boundary's inspection gets `suspense: { cause }`. `causeOf(boundary, recorded)` reads `memoizedProps.children`: a lazy carrying a Server Component's info (`_payload._debugInfo` or its own `_debugInfo`, a Flight chunk still streaming) is `server` with its name; a lazy or an element of a lazy type is `lazy`; then React 18's record, if any; a DOM element, text or a list is `promise`; any other element is `inside` with its type's name (React 19 doesn't say which component suspended). An arrived boundary gets `suspense: { awaited }` instead, when it has any: `tree.serversUnder(id)` (server nodes under it, not inside a nested boundary) with each one's `awaitsOf` and `owner: info.name`, at most 50.
- React 18's suspender (`createSuspended()`): React 18 development renderers expose `injectProfilingHooks`; while watching, the agent injects `{ markComponentSuspended(fiber, wakeable) }` into each, recording per boundary (the suspender's nearest tag 13, both fibers of the pair) the first suspender's name and the set of wakeables: `{ kind: "thrown", name, count }`. Only when the target has no own `__REACT_DEVTOOLS_GLOBAL_HOOK__` (ours sits on the prototype; an own one is another devtools, and the hook has one slot, which RDT's Timeline uses): then React 18 gets `inside` like 19. A boundary whose content arrives drops its record (`onArrive`); unwatch injects `null` and drops all records; a record is used only while injected. React 19 has no such hook.
- Arrivals (M7 #81): the tree calls `onArrive(fiber, id, ms)` when a waiting boundary's content arrives; the agent collects them during the commit and hands `recorder.commit(rootId, updaters, walk, arrivals)` a function that drains them after the walk, each an `Arrival` `{ boundary, name, waited, awaits }`: `name` the first server node under the boundary (`serversUnder`), else the first component it shows (`clientsUnder`; Next's client components arrive as lazy references, resolved by now), else "Suspense"; `waited` the wait; `awaits` `waitedOn(id)`. The recorder keeps them on the commit, and `summaries()` adds `arrived` when there are any.
- Props from the server apply to component fibers only (tags 0, 1, 11, 14, 15): a Suspense a Server Component rendered had a pending Flight chunk measured as 51 KB of props.
- Server Components (M7 #79, `src/server.ts`): a server node has no fiber; `tree.server(id)` gives its `info` and `entries`, the `_debugInfo` array holding it (on its first fiber below, or the nearest ancestor of that fiber that holds it: a keyed Fragment's). Inspecting it posts `props` (`info.props`, or `{}`), `owners` (from `info.owner`), `source` (`renderedAt(info)`: `info.stack[0]`, `[name, file, line, column]`, where the parent's JSX rendered it, as `{ url: "file://<file>", line, column }`; Next's file is an absolute server chunk path) and `server: { awaits, rendered }`; no state, hooks or contexts. `awaitsOf(info, entries)`: the `{ awaited }` entries whose `owner` is the info, named by the entry's own `stack[0]` function (the app's call, `getProduct`) or else `awaited.name` (`sleep`, the innermost), with `awaited.start`/`end` (performance clock); the owner-less `rsc stream` entry and other components' awaits are left out. `rendered`: `tree.clientsUnder(id)`, the component fibers (function, class, forwardRef, memo, lazy) with no component between them and the node (DOM, Suspense and providers walked through; server nodes stop), each `{ id, name, ...sizeOf(memoizedProps) }`. On the flush a server node is re-sent only for a new info object (a new payload), and dropped once it leaves (`tree.server` undefined, no fiber).
- Props from the server (M7 #79): a fiber whose `_debugOwner` is a Server Component (a `ReactComponentInfo`: no numeric `tag`, a string `name`) gets `fromServer: { owner: { id: tree.serverId(info) ?? null, name }, props: propSizes(memoizedProps) }`. Owners by the same rule (`serverOwner`) now carry a mounted server node's id.
- Sizes (`src/size.ts`): `sizeOf(value)` is `JSON.stringify(value).length` counted without running app code (own enumerable data properties through descriptors; getters, and `toJSON` other than Date's, aren't called), `{ bytes, over? }`. It stops, `over: true`, past `MAX_SIZE` (1 MiB counted), 32 levels, 100,000 values or a cycle; the value budget bounds the time (a 200,000-item array stops in well under 100 ms). `largestFields(value, 3)`: a plain object's own fields by size, largest first. `propSizes(props)`: one size per prop key (at most 100), and a prop over 10 KB with its 3 largest fields.
- `test/inspect-agent.test.ts`: props, class state, unknown and malformed ids, re-sends, no re-send for a sibling's commit, stop on `inspect null` and `unwatch`, expand, released ids, copy and store of props and hooks, targets that find nothing. `test/context.test.ts`: copying a context by read order.

## Hooks (`inspectHooks(fiber, dispatcherRef)`, `src/hooks.ts`, `src/stack.ts`; M4 #34)

The inspection's `hooks` come from a shadow render, after react-debug-tools' `inspectHooksOfFiber` (MIT, what RDT uses), rewritten here.

- Only function (tag 0), forwardRef (11, `render(props, ref)`) and simple memo (15) fibers have hooks; others get no `hooks` field. A lazy or memo-wrapped type's `defaultProps` are merged into its props.
- The agent finds the fiber's renderer (walk `return` to the HostRoot, tag 3, whose `stateNode` is in `record.roots`) and takes its `currentDispatcherRef` from the global hook's `renderers` map. React 19 keeps the dispatcher at `.H`, React 18 at `.current`.
- The component is called once with a stub dispatcher (a Proxy: an unknown hook throws "Unsupported hook: <name>" rather than misreading the list). Each stub reads the next entry of the fiber's `memoizedState` hook list and the next `fiber.dependencies` context (`memoizedValue`), mirroring what React allocates: Transition and SyncExternalStore take 2 entries, ActionState/FormState 3; contexts, `use`, DebugValue and FormStatus (a host transition context read) none.
- Values: State, Reducer, DeferredValue, Id, Optimistic, SyncExternalStore: the state. Ref: `.current`. Memo, Callback: the memoized value. Effect, LayoutEffect, InsertionEffect: their deps (no `value` without deps). ImperativeHandle: the ref's current handle. Transition: `isPending`. ActionState/FormState: the state (a fulfilled thenable's value). `use(context)` and `useContext`: `Context(<displayName>)` or `Context`. `use(thenable)`: `Use` with its value; thenables come from `dependencies._debugThenableState` in order, else the argument; a pending one ends the render where React would suspend (the hooks so far stand), a rejected one throws. EffectEvent: the function. `useMemoCache` (React Compiler) returns an empty cache and isn't listed.
- Grouping: `Error.stackTraceLimit` is raised for the render. Each stub records its stack; the frames between React's one exported wrapper and the shadow render's own frame (counted against a stack taken just before the call) are the custom hook chain. Each level is a group named after its function, keyed by its call site (the frame's source line), so consecutive hooks share a group only while their chains match, and two calls of one custom hook stay apart. A DebugValue inside a group becomes the group's `value` (formatter applied); at the top level it's its own row.
- Call sites (M4 #37): each hook gets `site` (`frameLocation`, `src/source.ts`): a built-in hook's is the frame below React's exported hook (`frames[ABOVE]`, the component or custom hook calling it); a custom hook group's is the caller frame its key uses. Real stacks, so React 18 and 19 alike. The panel names the hook from that line.
- `parseStack(stack)`: `{ functionName, source }` per frame, V8 (`at name (url:line:col)`) and Firefox (`name@url:line:col`) formats.
- No side effects: every `console` method is a no-op during the render; stub setters do nothing; effects never run. Any throw (except the suspend) becomes `hooksError`, with props and state still sent.
- `test/hooks.test.ts` (React 18 and 19, through the agent): built-ins in order with values, live re-send, custom hook groups, React 19 hooks, no effects/commits/logs, throw, suspend, forwardRef, memo, class. `test/stack.test.ts`.

- Boundaries (M5 #56, `src/boundaries.ts`): `boundariesOf(fiber)` is the nearest Suspense boundary (tag 13) and error boundary (a class, tag 1, with `getDerivedStateFromError` or `componentDidCatch`) at or above the fiber; the inspection sends them as `boundaries` by tree id (`tree.known`) with `on`. `force { id, kind, on }` (inspected node only) goes through `createForcing(renderer)`, one per renderer, which installs React's handlers on its first force (a page that never forces keeps any handler already there): `setSuspenseHandler` (asked about each Suspense fiber as it renders; true shows its fallback) and `setErrorHandler` (asked about each class component; true renders its error UI for a simulated error, false resets it to a fresh instance's state, undefined leaves it). On: the boundary (a fiber and its alternate are one) joins the forced set and `scheduleUpdate`. Off: it leaves; an error boundary is `resetting` for one render (`scheduleUpdate`), a Suspense boundary renders again on `scheduleRetry` (React 19) or `scheduleUpdate` (React 18). The node's props and state didn't change, so the agent posts the inspection itself after the commit. Showing the fallback hides the node (its fiber leaves the tree) and the error UI unmounts it, so turning a toggle off goes to the boundary (the panel selects it on turning one on).
- `rerender { id }` (M5 #55): for the inspected node only, not a DOM element (tag 5) or text (tag 6): `renderer.scheduleUpdate(fiber)` renders it again with nothing changed, so its root commits once (with nothing new, React bails out of the component after calling it, as for any update with equal values); the immediate re-send follows.
- Context edits (M5 #54): root `{ context: i }` is written through context `i`'s provider, found at edit time from the current fiber's reads (`contextsOf`, `providerOf`): `applyEdit` runs its props branch on the provider fiber with `["value", ...path]` (React has no context override; writing the provider's `value` prop updates every reader, memo ones too). A default read (no provider) is ignored.
- Hook list index (M5 #50; every hook since M6 #59): `inspectHooks` counts the hook list entries it reads (`next()`); each hook that reads the list records the position of its first entry as `RawHook.index`, which `overrideHookState` takes for a state hook and M6 render insight uses to name changed hooks. Context reads, `use(thenable)` and `DebugValue` read no entry and have none. Not call order: a transition and a sync external store take two entries, `useActionState` three. `hookPath(hooks, index)` gives the call indexes (what `hookAt` takes) of the hook at a list index, through custom hooks; `hookLabel(hooks, index)` its label as the panel's Hooks section numbers rows (`State #7`, depth-first, group rows counted), for hooks of a component other than the inspected one. Page-only: `describeHook` doesn't send it. Likewise `useContext` and `use(context)` keep the context object as `RawHook.context`; `describeHook` sends its index in the contexts list (read order, the Context section's `{ context: n }`) as `HookValue.context`, so the panel can send the hook row's edit to that context's row, and leaves it out if the context isn't in the list (a -1 would make the panel drop the whole inspection).
## Render insight (`createRecorder()`, `src/insight.ts`; M6 #61)

- **When:** only while watched. Each commit the agent calls `recorder.commit(rootId, updaters, walk)`, with `walk` the tree's commit walk (`tree.commit(..., onVisit)`), so nothing walks twice. `unwatch` calls `clear()`; commits before `watch` aren't recorded.
- **Updaters:** `new Set(root.memoizedUpdaters)`, read inside `onCommitFiberRoot`: React keeps the fibers that scheduled the committed update there in dev builds whenever a devtools hook was present at load, and clears it right after the hook returns (18.3 and 19.3).
- **Which fibers:** function, class, forwardRef and memo components (tags 0, 1, 11, 14, 15) that did work (`flags & 1`, PerformedWork), or that are among the updaters: a function component re-run by `scheduleUpdate` with nothing changed bails out before React flags the work.
- **Reasons (`RenderRecord`):** `mount` (no alternate), else any of `props` (keys differing by `Object.is` over both objects' keys, `{ key, old, new }`), `state` (a class's state keys, `state`; else hooks with an update queue whose `memoizedState` changed, `hooks: { index, old, new }` by hook list index; a ref, memo or effect entry has no queue), `context` (by this render's read order, `contextsOf`, a context read in both renders whose value changed). None of those: `force` if it's an updater, else `parent`.
- **Effects (M6 #63):** `effects` lists the effects a re-render ran (none on mount, where every effect runs). An effect hook's list entry holds its effect object (`{ tag, create, deps, next }`, plus `destroy` on 18 or `inst` on 19), which is also in the ring at `fiber.updateQueue.lastEffect`; walking both renders' hook lists, an entry whose `memoizedState` is in the current ring with `tag & 1` (HasEffect) ran: `{ index, changed }`, `changed` the deps differing (`Object.is`) from the alternate's effect as `{ dep, old, new }`, or no `changed` for an effect with no deps array. Every kind is in the ring: `useEffect`, `useLayoutEffect`, `useInsertionEffect` (and `useImperativeHandle`, a layout effect).
- **Remounts (M6 #64):** a mount (kind `mount`) in the place of a same-type fiber this commit deleted gets `remount`. React lists a parent's deleted children in `deletions` until the parent is next reused, their subtrees still linked during `onCommitFiberRoot` (passive effects detach them after; recording outside the hook misses them). From the mounted fiber up while the parent is new: the highest new fiber `top`, whose parent survived. The old fiber is the one in that parent's `deletions` with `top`'s `.index`, then the same child indexes down; same `elementType` there: remounted. `top` itself: `{ cause: "key", from, to }`; below it: `{ cause: "ancestor", ancestor }`, the nearest emitted new fiber above it (by this commit's visited ids; the walk visits parents first), or `top`'s key change if none is emitted. Only the deleted list counts, so a keyed sibling that moved, or a component shown again in a later commit, is a plain mount.
- **New references (M6 #62):** a changed prop gets `reference: "new-function"` when both values are functions, or `"same-value"` when `sameValue` finds them equal: plain objects (prototype `Object.prototype` or null) and arrays compared key by key through own descriptors (no getter runs; an accessor counts as different), anything else by `Object.is`, at most 1,000 values read (`MAX_COMPARED`; past that it's a change). Props only: a class's state keys and hooks aren't marked.
- **Triggered by (M6 #65):** each commit keeps `updaters`, the ids of the component fibers among the updaters (current or alternate). A root `render()` lists the HostRoot fiber, not a component, so it has none. `updatersOf(seq)` gives `{ id, hooks }`, `hooks` that updater's own record's state changes in the commit (an updater always gets a record); an unknown seq gives `[]`.
- **Commits (M6 #67, #69):** `summaries(after)` gives `{ seq, time, rootId, updaters, renders }` (`CommitSummary`, `time` from `Date.now()`, `renders` the count of records) for each buffered commit after a seq; `rendered(seq)` that commit's `{ id, kinds }` per record in walk order (undefined once it's dropped). The agent's flush, after the tree batch, posts `commits` (`docs/messages.md`) with `summaries(sentCommit)`, in batches of at most 100 (`MAX_HISTORY`) each carrying `oldest()` and `dropped()` (#71), and moves the cursor to the last; `watch` posts the whole buffer the same way right after the tree's reset (#70: even empty, without waiting for a commit, so a panel reconnecting to an idle page gets its list back) and moves the cursor to its last. A `commit { seq }` posts `committed(seq, renders, updaters)` batches of at most 2,000 (`MAX_OPS`; at least one, empty for a commit that rendered nothing), the first with `triggers(seq, serialize)` (the updaters labelled like Hooks and serialized with a fresh `createInspector()`; `reasonOf` uses the same helper with the selected node's hooks), or `committed(seq, null)` once it's dropped.
- **Updates (M6 #74):** `summaries` gives `wasted`, the commit's records whose kinds are exactly `["parent"]` (`isWasted`, shared with the counts). `postCommits` adds `change` to a summary with updaters: the first updater's first changed hook as `{ hook, old, new }` (list index, values through a fresh `createInspector().serialize`); no label, which would take `inspectHooks` (a shadow render that runs the updater's code again, and swaps in a no-op setter for components that keep one from render) on every update. `clear-updates` runs `clearCommits()` (empties the buffered commits and `dropped`, keeps `latest` and the counts) and posts the empty list.
- **Counts (M6 #72):** each recorded render adds 1 to its id's `renders`, and to `wasted` when its kinds are exactly `["parent"]` (it rendered only because its parent did); since the watch, not bounded by the buffer, dropped by `forget(id)` (an unmount) and `clear()`. `takeCounts(all)` returns `{ id, renders, wasted }` for the ids changed since the last call (`all`: every id) and resets the changed set. The flush posts the changed ones after `commits` (none changed: nothing), `watch` all of them (at least one message), in `counts` batches of at most 2,000 (`MAX_OPS`; `docs/messages.md`).
- **Buffer (M6 #71):** commits of `{ seq, time, rootId, records, updaters }`, `seq` from 1 per recorder, bounded by records, not commits: past 20,000 records (`MAX_RECORDS`) or 1,000 commits (`MAX_COMMITS`), whole commits drop oldest first, the newest always kept whole however many it rendered (`createRecorder({ maxRecords, maxCommits })` for tests). `dropped()` says one dropped since the last `clear()`; `oldest()` is the oldest buffered seq (the next one's when empty). Records hold references to the old and new values, nothing serialized; a dropped commit drops its references. Each component's newest record is also kept in a map, past its commit's drop, until the tree forgets the id (`createTree({ onForget })` calls `recorder.forget(id)` for each id an unmount drops, descendants too) or `clear()`: `latest(id)` reads it, `record(id, seq)` falls back to it, and `history(id)` (the seqs of its buffered records, oldest first) puts its seq first when its commit dropped, then keeps the last 100 (`MAX_HISTORY`). Measured in `docs/bench.md` (Recording memory).
- **Time (M6 #73):** every record of a commit carries that commit's `time` (`Date.now()`, read once per commit, the summary's too), so a component's latest record says when it rendered after its commit drops; `reasonOf` sends it.
- **Sent:** `describe` adds `render` (`docs/messages.md`, Render reasons) from `latest(id)`: values through the inspection's `serialize` (lazy, released with it), keys cut to 256 chars, lists to 1,000, hooks as call indexes (`hookPath`; an index no inspected hook starts is left out), contexts by read index. `updaters` from `updatersOf(seq)` (at most 1,000), each hook change labeled with `hookLabel`: over the inspected hooks when the updater is the inspected node, else over the updater's own `inspectHooks` (read only when it changed hooks); a change without a label, or an updater no longer in the tree, is left out. With `render`, `history` (M6 #66) is `history(id)` (non-empty then). A `reason { id, seq }` for the selected node posts `reasoned(id, seq, render)`: `record(id, seq)` through the same `reasonOf` and inspection serializer (its values released with the inspection), or `null` once the commit left the buffer; for any other node, nothing. `refresh` also re-sends when `latest(id)?.seq` isn't the one sent, so a forced render (same props and state) shows.
- **Tests:** `test/insight.test.ts` (the recorder on React 18 and 19, through a real tree), `test/inspect-agent.test.ts` (sent with the inspection, only while watched).
